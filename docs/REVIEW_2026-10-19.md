# Correcciones de funcionamiento — 19 de octubre de 2026

La revisión siguió el código del flujo público: navegación, captura/OCR, revisión, clientes, plantillas, generación, archivos e historial; se contrastaron las escrituras y rutas con las funciones SQL y políticas vigentes. También se ejecutaron comprobaciones de tipos, pruebas automatizadas y auditoría de dependencias.

## Fallos corregidos

- Guardar una identidad y luego continuar podía intentar crearla de nuevo. La revisión conserva el ID y revisión confirmados y permite continuar aunque la recarga del listado falle. La confirmación y los errores están junto a las acciones.
- El ID `doc-UUID` generaba una ruta incompatible con la política de Storage, que exige un UUID sin prefijo para el archivo. Los documentos nuevos usan UUID válidos. Las pruebas simulan también esa restricción real.
- Un cliente recién guardado podía faltar en el selector cuando había fallado la recarga; se conserva la selección recibida. Una escritura confirmada mantiene el cliente o plantilla visibles aunque falle la actualización posterior.
- Mientras un Word queda pendiente de archivar, no se puede cambiar el cliente, la plantilla o el letrado y mezclar los datos con el archivo preparado. El trabajo en curso activa la protección de cambios sin guardar.
- Las búsquedas podían ser sobrescritas por respuestas antiguas. Se descartan respuestas obsoletas y se protege la paginación. Se buscan plantillas/números de identidad en las páginas históricas, y correo/teléfono/nombres con tildes entre los clientes ya cargados.
- La ficha de un cliente solo usaba los documentos de la vista global, que puede estar paginada o filtrada. Ahora consulta todo su historial por ID sin alterar el historial global; cancela el seguimiento al cerrar la ficha.
- Sexo desconocido aparecía como femenino. Ahora se muestra «Sin confirmar» o «Otro / no especificado» según corresponda.
- Los errores de guardado podían quedar detrás de los diálogos. Son visibles dentro de las fichas y plantillas. Los botones de cierre/guardado respetan las operaciones en curso y las plantillas conservan el ID al reintentar.
- Se protege la salida con datos de clientes, plantillas o una lectura OCR sin guardar. «Nuevo documento» pide una sola confirmación.
- Las diferencias de puntuación entre la identidad impresa y la MRZ no impiden combinar ambas caras. Una captura nueva de cámara limpia el reverso anterior. La revisión conserva la imagen original y los mensajes respetan el idioma elegido.
- Si la inicialización del motor OCR fallaba sin devolver una promesa, podía quedar bloqueado para posteriores lecturas. Se recupera correctamente.
- Un ZIP sin documento principal de Word podía aceptarse como plantilla; ahora se rechaza.
- Se muestran las fechas del historial en la zona de Panamá y los recuentos de páginas se identifican como archivos mostrados.

## Verificación

- 48 pruebas Node: mapeo, Word, MRZ, fechas, identidad, almacenamiento, búsquedas concurrentes, recuperación de OCR y validación de plantillas.
- Chromium: Word preparado → fallo de archivo → reintento con ID/ruta estables → descarga; revisión → guardar → fallo temporal → reintento → generador; ficha de cliente con sexo desconocido e historial antiguo; errores visibles en el diálogo.
- OCR real sobre documento ficticio: lectura → vencimiento → revisión → guardar → generador, interceptando las escrituras para no crear clientes de prueba en Supabase.
- Auditoría de dependencias: cero vulnerabilidades conocidas en la ejecución de esta revisión.
- CI repite TypeScript, pruebas, compilación, PostgreSQL, navegador y comprobación de Edge Function antes de publicar.

No se modifican los permisos de acceso público ni se requiere otro SQL. Las fotos reales de todos los países, cámara física y maquetación en cada versión de Word necesitan comprobaciones adicionales con muestras y dispositivos; las pruebas automatizadas no garantizan ausencia absoluta de errores.
